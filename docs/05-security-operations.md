# Безопасная эксплуатация онлайн-контура

## Перед запуском

- запретить вход SSH по паролю, оставить ключи и ограничить адреса в firewall;
- включить автоматические security-обновления ОС;
- хранить `.env` только на сервере с правами владельца;
- выдать S3-ключу минимальные права на один приватный bucket;
- включить versioning/lifecycle для bucket и отдельные зашифрованные копии
  PostgreSQL с проверяемым сроком хранения;
- настроить внешний мониторинг `/healthz`, свободного места и срока TLS;
- собирать технические логи без токенов, ciphertext и полей профиля;
- проверить восстановление PostgreSQL и S3 на отдельном стенде до релиза.

## Регулярные операции

Обновления контейнеров сначала проверяются на staging. Перед изменением схемы
создаётся снимок PostgreSQL, затем применяется `alembic upgrade head`. Секрет JWT
нельзя менять без плана принудительного выхода всех устройств. S3-ключ меняется
созданием второго ключа, проверкой загрузки, затем отзывом первого.

Проверки зависимостей и статический анализ нужно запускать в CI на каждый pull
request. Release APK/AAB подписывается отдельным ключом, недоступным серверу сборки
обычных веток. Для публикации фиксируются SHA-256 артефакта и версия исходников.

## Инцидент

При подозрении на утечку сначала закрывается источник, сохраняются журналы и время
событий, затем отзываются затронутые S3-ключи и сессии. Компрометация сервера сама
по себе не раскрывает содержимое E2EE-задач, но раскрывает метаданные, профили и
социальный граф. Компрометация разблокированного телефона может раскрыть локальные
данные и ключи доступных пространств, поэтому пользователю нужна блокировка экрана
и актуальная версия Android.

После устранения причины ключи общих пространств повышаются до новой версии,
участникам выдаются новые конверты, а старые устройства отзываются. Итоговый отчёт
должен содержать затронутые данные, интервал, способ обнаружения, исправление и
меры против повторения.

## Данные и удаление

До публичного запуска нужны политика конфиденциальности и пользовательское
соглашение с перечнем метаданных, местом хранения, сроками, экспортом и удалением.
API немедленно блокирует аккаунт при запросе удаления и обезличивает профиль.
Production-эксплуатация должна выполнять журналируемую фоновую очистку строк и
объектов S3 после установленного срока отмены. До появления такого задания функцию
удаления нельзя описывать пользователю как мгновенное физическое стирание.
