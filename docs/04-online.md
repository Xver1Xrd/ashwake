# Онлайн-контур Ashwake

Онлайн-функции сделаны опциональными. Room остаётся источником данных на
телефоне, интерфейс работает без сети, а WorkManager отправляет изменения после
возвращения подключения. Если `ashwake.apiBaseUrl` не задан, экран аккаунта
показывает инструкцию, а остальная часть приложения работает как раньше.

## Что реализовано

- профиль с уникальным `@username`, именем, bio и настройками видимости в API;
- точный поиск по username без выдачи общего каталога пользователей;
- заявки в друзья, принятие, отклонение, удаление и блокировка;
- приглашение одного партнёра и общее пространство «Мы»;
- личные, парные и произвольные общие пространства с ролями owner/editor/viewer;
- привязка задач к пространству и фильтрация в списке;
- синхронизация изменений и удалений с ревизиями и фиксацией конфликтов;
- ежедневная зашифрованная копия в S3 и восстановление последней копии после
  проверки контрольной суммы и явного подтверждения;
- добавление нового телефона с помощью кода восстановления.

## Модель защиты

При регистрации Android создаёт два P-256 ключа: ключ подписи для входа и ключ
ECDH для получения ключей пространств. Закрытые ключи находятся в Android
Keystore. На Android 12+ оба ключа генерируются непосредственно в Keystore; на
Android 8–11 ECDH-ключ хранится в виде зашифрованного контейнера под мастер-ключом
Keystore из-за ограничений старого API.

Для входа сервер выдаёт случайный одноразовый challenge. Телефон подписывает его,
сервер проверяет подпись публичным ключом и возвращает access-токен на 10 минут и
вращаемый refresh-токен. Сервер хранит только SHA-256 refresh-токена. Повторное
использование уже заменённого токена отзывает все сессии этого устройства.

Каждое пространство имеет случайный AES-256 ключ и номер версии. Запись задачи
шифруется AES-GCM с привязкой `spaceId:keyVersion` как AAD. Ключ пространства
передаётся устройству в конверте: эфемерный P-256 ECDH, HKDF-SHA256 и AES-GCM.
Сервер проверяет членство и роль, но видит только ciphertext, служебный тип записи,
UUID, ревизию и время изменения.

Код восстановления содержит 256 случайных бит и показывается один раз. На сервере
находятся его SHA-256 и зашифрованный им набор ключей пространств. Облачный архив
также шифруется кодом восстановления. Потеря всех доверенных устройств и кода
означает потерю доступа к зашифрованным данным; сервер расшифровать их не может.

## Синхронизация

Локальная задача получает глобальный UUID, `spaceId`, серверную ревизию и состояние
`LOCAL/PENDING/SYNCED/CONFLICT`. При первом входе существующие локальные задачи
переносятся в личное пространство. Отправка использует ожидаемую базовую ревизию.
Если сервер уже содержит новую версию, локальная запись становится конфликтной,
а удалённая версия сохраняется отдельно для последующего разбора.

Удаления передаются tombstone-записями. Серверный change log даёт монотонный
курсор; клиент забирает страницы до `has_more=false`. Фоновая синхронизация
запускается не чаще раза в 15 минут и только при наличии сети.

## Локальная разработка

```bash
cd server
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
export ASHWAKE_ENVIRONMENT=development
export ASHWAKE_JWT_SECRET="$(openssl rand -base64 48)"
.venv/bin/uvicorn app.main:app --reload --port 8080

# В другом терминале
./gradlew :app:assembleDebug -Pashwake.apiBaseUrl=http://10.0.2.2:8080
```

HTTP разрешён только debug-варианту. Release-сборка принимает только HTTPS.

## Production

1. Создать VM с Ubuntu, приватный S3 bucket и отдельный S3 access key с доступом
   только к этому bucket.
2. Направить A/AAAA-запись поддомена API на VM и открыть входящие 80/443.
3. Скопировать каталог `server`, создать `.env` по `.env.example` и сгенерировать
   независимые случайные `POSTGRES_PASSWORD` и `ASHWAKE_JWT_SECRET`.
4. Выполнить `docker compose up -d --build`. Caddy автоматически получает TLS,
   а API перед стартом выполняет `alembic upgrade head`.
5. Проверить `https://api.example.ru/healthz`, затем собрать Android с
   `-Pashwake.apiBaseUrl=https://api.example.ru`.

PostgreSQL и API не публикуют порты наружу; доступен только Caddy. S3 bucket должен
оставаться приватным: загрузка и скачивание идут по короткоживущим подписанным URL.
Секрет S3 находится только на сервере.

## Границы текущей версии

Синхронизируются задачи. Привычки, отказы, рутины и остальные локальные сущности
попадают в зашифрованный полный архив, но ещё не редактируются одновременно на
нескольких устройствах. При создании пары владельцу пространства нужно хотя бы
один раз открыть экран профиля, чтобы сформировать конверты ключа для устройств
партнёра. Закрепление сертификата следует включать после выбора постоянного домена
и схемы ротации сертификатов; системная проверка TLS уже обязательна в release.
